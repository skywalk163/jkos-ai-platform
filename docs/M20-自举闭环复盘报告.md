## 一、目标与本轮实质

M20 的目标一句话：**JKOS 管理 JKOS** —— 用 M17 建成的自动化优化引擎驱动 JKOS 自身的「探索 / 复盘 / 优化」流程，并与 deepseek-harness 融合形成自举闭环。

**本轮要解决的真实缺口**：`jkos_core/optimization/` 的 `OptimizationEngine` 门面虽有「缓存 / 模板 / 探索」三层路径，但

- 它的**探索层是模拟实现**（`automation_engine.py` 按 `EXPLORE_BASE=1500 × EXPLORE_SUBTASKS=10` 假算出 15000 Token，`execute_with_exploration` 并不调用任何真实引擎）；
- 真实引擎 `jkos_core/exploration/`（分解 → 检索 → 搜索 → 实验 → 沉淀）与 `ProcessSolidifier.solidify()` / `TemplateManager.create_template()` **之间没有任何调用关系**。

也就是说，M20 之前「自举」只存在于文档里，代码上不成立。本轮的实质就是**把这条链路真正打通，并用可量化证据证明闭环成立**。

## 五、混合模式双跑对比

两条路径在同一 task 下均 `M20.3-DEMO-OK`：

| 路径 | LLM 元数据 | D3 生成方式 | 结果 |
| --- | --- | --- | --- |
| 默认（接真实 LLM 路由，本机无凭据） | `used=true, simulated=true, provider=simulated, tokens=199` | 自动回退 `fallback` | 闭环成立 |
| `--no-llm`（显式离线） | `used=false` | `fallback` | 闭环成立 |

**降级判定依据**：`comps.llm` 类型为 `LLMRouter`（`bootstrap.py`），**永不为 None**；无 API Key 时 `DeepSeekProvider` 的 `healthy()` 为 False 被路由器跳过，链路末尾的 `SimulatedProvider` 恒健康并返回 `simulated=True` 的 `[模拟输出]` 文本。因此判定必须基于 `result.simulated`，判断 `llm is None` 会失效。

有凭据时（0.82 验收环境）走真实生成；LLM 生成的用例要经「语法校验 → 导入白名单 → 危险名拒绝 → 实际运行」四关，任一关不过即回退确定性模板，保证演示不因模型输出抖动而失败。

## 八、实施中发现并修正的三个问题

1. **`inspect.iscoroutinefunction(实例)` 为 False**：`Experimenter._run_one` 用它区分同步/异步执行器，可调用实例（`__call__` 为 async）会被判为同步并丢进 `asyncio.to_thread`，拿到未 await 的协程对象而静默"成功"。**修法**：传递**绑定方法** `d3.run_as_executor`（`ismethod` 为真、可正确识别），并在模块 docstring 与测试中锁住该契约。
2. **`require_approval` 不能硬编码 `pending_approval=True`**：`AutomationEngine.execute` 在任务已有可推荐模板时**直接走模板执行、不挂起审批**（既有语义）。**修法**：按 `run.meta.status` 如实回传，并补两条用例分别覆盖「无模板 → 挂起」与「有模板 → 不挂起」。
3. **闭环成立判据必须含 `template_hit`**：仅「四段都 OK + 探索成功」不足以证明引擎学到了该任务 —— 若推荐被内置 61 个业务种子模板抢走，复现用的就不是本次新建模板。**修法**：`success` 增加 `template_hit` 条件。

## 九、已知问题与边界（如实记录）

| # | 问题 | 影响 | 处置 |
| --- | --- | --- | --- |
| 1 | 模板推荐的排序是 `task_kw + 0.5 × keyword_score(task, description)`，**种子模板的描述若覆盖查询词，得分可超过本次新建模板的精确 task 匹配** | 任意业务化 task 文案下闭环可能"未成立"（实测「为 label 生成单元测试」：种子 1.333 > 本次 1.042） | 演示/验收统一使用有区分度的 task（`DEFAULT_TASK` 含独有词 `selfboot`，实测本次 1.013 > 次优 0.5）；已在用例中锁住该边界语义 |
| 2 | 覆盖率按被测函数行区间统计，只覆盖「空/零值入参」这一条分支 | 覆盖率数字（如 80%）反映的是确定性兜底用例的覆盖深度，非函数全分支覆盖 | 如实标注 `coverage_source`（real / proxy）；LLM 路径可生成更深的边界用例 |
| 3 | 确定性兜底按注解/命名猜安全入参，注解缺失且非文本参数时回退空串 | 对少数非文本纯函数可能产生失败用例 | 运行失败会如实反映在 `passed/failed`，不影响其它段；生产目标函数建议带注解 |
| 4 | 探索/优化组件内部用 `with sqlite3.connect(...)`（上下文管理器只提交事务、不关闭连接） | Windows 下临时目录清理可能报文件占用；运行时产生 `ResourceWarning` | 属既有实现，本轮未改动（超出 M20 范围）；已在报告中记录 |
| 5 | 内置 61 个种子模板参与推荐竞争 | 新建模板未必被推荐命中 | 见 #1 处置；后续可考虑「精确 task 匹配优先」的排序微调 |
| 6 | `nats-py` 对不可达 NATS 的连接重试远超 `connect_timeout=3`（实测单次约 4 分钟） | 本地（无 NATS 服务）全量回归被拖长至 36 分钟 | 属既有实现（`NatsEventBus.connect()` 已设超时但被内部重试覆盖）；本轮未改动，建议后续显式限制 `max_reconnect_attempts` |
